Privacy Policy

Last updated: 18 October 2026

Blackboard Sync is a free, open-source app for macOS and Windows that downloads your course content from Blackboard Learn to your own computer. This page explains what the app stores on your computer, what it sends over the internet, and how you can delete it. The app’s source code is public on GitHub, and every statement here is based on that code.

Which version you have

Blackboard Sync comes in three builds. Most of this page applies to all of them; where a statement applies to only some, it says so.

  • macOS: the app downloaded as a .dmg from GitHub or this website.
  • Windows Setup: the app installed with Blackboard-Sync-…-Setup.exe from GitHub or this website.
  • Microsoft Store: the Windows app installed from the Microsoft Store (an MSIX package). See Microsoft Store build for how it differs.

In short

  • The app never sees or stores your password.
  • Your sign-in session, settings and download records stay on your computer.
  • It connects to your school’s Blackboard address (and its sign-in and file redirects), and to Google if you enable optional Google Calendar sync. The macOS and Windows Setup builds also contact GitHub to check for updates; the Microsoft Store build does not.
  • No analytics, ads or usage tracking (telemetry), and no account to create.
  • Your data is not sold. If you enable Google Calendar, deadline information is sent to Google at your request.

Your password and sign-in

You sign in on your school’s own Blackboard sign-in page: either in a Chromium-based browser installed on your computer (Chrome, Edge, Brave and similar), using a separate browser profile reserved for the app, or, if there is no such browser, in the app’s own sign-in window (WKWebView on macOS, Microsoft Edge WebView2 on Windows). You type your password and any two-step verification code into that page; the app does not see, read or store them.

Once you are signed in, the app takes and saves only the session cookies that belong to the Blackboard address. Cookies of your school’s single sign-on (SSO) provider are not saved.

What is stored on your computer

The app keeps its data in a folder that only your user account can access:

  • macOS~/Library/Application Support/blackboard-sync
  • Windows Setup%APPDATA%\blackboard-sync
  • Microsoft Store%LOCALAPPDATA%\Packages\<package family name>\LocalCache\Roaming\blackboard-sync

That folder contains:

  • Session (session.json): the Blackboard address, the Blackboard session cookies, and the user ID, user name and display name Blackboard reports. It contains no password. The file is updated when Blackboard renews the cookies.
  • Sign-in data: the separate browser profile used for sign-in (browser-profile) and, on Windows, the web data of the sign-in window (inapp-profile). On macOS, the sign-in window’s web data is kept by macOS in the app’s WebKit storage.
  • Settings (settings.json): your school’s Blackboard address, the download folder, the sync interval, and whether automatic update checks are on.
  • Download records (state.json, last-run.json, menubar.json): which course items were downloaded, their local paths, file digests (SHA-256) and sizes, and the result of the last sync. They are used so the same file is not downloaded twice and so files you deleted can be listed under “Silinenler” (Deleted).
  • Logs (menubar.log on macOS; windows-tray.log and windows-tray-faults.log on Windows): the app’s activity log, for troubleshooting. Logs never leave your computer.

Downloaded course files, and the Markdown notes created for announcements and links, are saved in a University folder inside the download folder you choose. The default is ~/Documents/University on macOS and the University folder in your Documents folder on Windows (all builds). If your Documents folder is synced by a service such as iCloud Drive or OneDrive, those files are synced under that service’s own terms; Blackboard Sync itself sends nothing to such services.

If “start when the computer starts” is on: on macOS a launch file is added to ~/Library/LaunchAgents; with Windows Setup, a value is added under your user’s startup registry key (HKCU\…\Run); the Microsoft Store build uses a Windows startup task instead (see below). An update the macOS app downloads is saved to a temporary folder or your Downloads folder; one the Windows Setup build downloads is saved to a temporary folder.

Optional Google Calendar

Only after you connect, the app sends event titles, course names, due times and Blackboard links to Google, together with technical event identifiers and hashes to match updates. It creates a dedicated secondary calendar named Blackboard Deadlines. It never writes to your main calendar or reads personal events. It reads only its own managed events in the dedicated calendar. Google reminders are off by default.

Google authorization runs in your system browser with PKCE and a temporary loopback callback at 127.0.0.1. The refresh token is stored in macOS Keychain or Windows Credential Manager; on other platforms it is saved in an owner-only local google-token.json. Access tokens remain in memory. The private data folder stores google-calendar.json (calendar ID, connection state, last sync and error) and google-calendar-events.json (Blackboard key to Google event ID and hash). If you disconnect while keeping the Google calendar, google-calendar-target.json retains only its non-secret calendar ID so a later connection can reuse or delete it. The token, event mapping and connection status are cleared. Deleting the dedicated calendar also removes the saved ID. Tokens are never logged. This feature uses only the calendar.app.created permission for app-created secondary calendars.

Disconnect in macOS Settings → Google Calendar, or run blackboard-sync calendar disconnect, to revoke the token and clear local Calendar connection data. Choose the confirmation checkbox or --delete-calendar to delete the dedicated calendar as well; otherwise its events stay in Google and stop updating. You may also revoke access at Google Account → Third-party connections. Revocation does not delete existing Google events. If permission was already revoked, reconnect before requesting calendar deletion, or delete the dedicated calendar directly in Google Calendar settings. Disconnect before uninstalling: removing local files does not itself revoke access or delete the remote calendar.

Blackboard Sync's use and transfer of information received from Google APIs adhere to the Google API Services User Data Policy, including the Limited Use requirements. Google user data is used only to provide this calendar feature, not for advertising, sale, or training generalized AI models.

Microsoft Store build

The Microsoft Store build is the same Windows app with a few differences in where it keeps data and what it connects to:

  • Private data folder. Its data (the session, sign-in data, settings, download records and logs listed above) is kept in the package’s own folder, %LOCALAPPDATA%\Packages\<package family name>\LocalCache\Roaming\blackboard-sync, not in %APPDATA%\blackboard-sync.
  • Separate from the Setup build. If you also installed the Setup build, the two keep separate data. The Store build starts with fresh settings and a fresh session, and does not use, move or delete the Setup build’s %APPDATA%\blackboard-sync folder. Downloaded course files are not moved or deleted either.
  • Start at login. It uses a Windows startup task declared in the package, not the HKCU\…\Run registry value. You turn it on or off in the app’s settings, and also in Task Manager → Startup apps or Windows Settings → Apps → Startup.
  • No GitHub contact, no self-update. It never contacts GitHub: it does not check for, download or install updates itself. Updates are delivered by the Microsoft Store.
  • Removal through Windows. There is no in-app uninstall. You remove the app in Windows Settings → Apps; Windows then removes the package’s private data folder. Your course files stay where they are.

Installing and updating the app through the Microsoft Store is handled by Windows and the Microsoft Store under Microsoft’s own privacy statement. Blackboard Sync itself sends no data to Microsoft.

What is sent over the internet

The app connects to:

  • Your school’s Blackboard address (the address you enter in the settings), in all builds. The course list, course content, announcements and files are requested from this address with your saved session cookies. If Blackboard redirects a file download to its own file storage address, the file is downloaded from there. During sign-in, your school’s sign-in page may redirect to your school’s single sign-on provider.
  • Google (accounts.google.com, oauth2.googleapis.com and www.googleapis.com), only when you connect optional Calendar sync: consent, token refresh/revocation, and management of Blackboard Deadlines as described above. Like any web service, Google sees your IP address.
  • GitHub (api.github.com and github.com), macOS and Windows Setup builds only: to learn whether a new version exists and to download it. The automatic check runs once a day and can be turned off with Check for updates automatically in the settings. The request includes the app’s version number; like any web request, GitHub sees your IP address. Updates are downloaded from GitHub’s file servers, and their size and the SHA-256 digest published with the release are checked before installing. The Microsoft Store build never makes these requests.

The network activity of the browser or sign-in window used for sign-in is up to the maker of that browser or component. The app talks to the sign-in browser only inside your computer (127.0.0.1).

No analytics or tracking

The app has no analytics, ads, usage statistics, crash reporting or other telemetry. It sends no data to any server run by its developer, and the developer receives no data about you. This website has no analytics or tracking tools either.

Sharing with third parties

Your data is not sold or rented. The app contacts your school’s Blackboard server, GitHub for updates in the macOS and Windows Setup builds, and Google when you opt into Calendar sync. Deadline information is transferred to Google only to provide that feature. These services have their own privacy policies.

Deleting your data

  • Sign out, in all builds: deletes the session file and all sign-in data (the sign-in browser profile and the sign-in window’s web data). Settings, download records and course files are kept.
  • Uninstall app… (in the settings, under Updates), macOS and Windows Setup builds: removes the app, its data folder (session, sign-in data, settings, download records, logs) and the start-at-login entry. If you tick Also delete the downloaded course files, the files the app downloaded are moved to the Trash / Recycle Bin too.
  • Microsoft Store build: remove the app in Windows Settings → Apps. Windows removes the package’s data folder with it. Delete the University folder yourself if you no longer want the course files.
  • By hand, macOS and Windows Setup builds: remove the app (on macOS move it to the Trash; on Windows use Settings → Apps), then delete the data folder listed above and, if you like, the University folder. On macOS you can also delete ~/Library/LaunchAgents/io.github.umutylcn.blackboard-sync.menubar.plist.

Children

The app is meant for students using their school’s Blackboard account and is not directed at children. It does not ask anyone for their age or any other personal information.

Changes to this policy

If the app’s use of data changes, this page is updated and the date above is changed. Earlier versions can be seen in the repository history on GitHub.
