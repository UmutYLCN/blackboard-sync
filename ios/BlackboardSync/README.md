# Blackboard Sync for iPad — foreground pilot

A native SwiftUI iPadOS 17+ app, developed separately from the desktop app and the untouched `prototypes/ipad-proof/`. Open **BlackboardSync.xcodeproj** in Xcode 26 and select the shared **BlackboardSync** scheme. The only package is the local `../BlackboardSyncFeatures` (announcements and due dates), which Xcode resolves from the repository; no remote packages, project generator, server, or desktop companion are needed.

The app uses the desktop icon, blue accent, system typography, sidebar order (the rounded **Open folder** button above Home, Sync activity, Announcements, Courses with a "4/5" badge while some course is unticked, and Calendar), the greeting with the next due dates under it, a top bar on every page, pushed folder pages included, with the page title at the left and **Pause / Resume**, **Settings** and the account initials as three equal circles at the right, all on one line (drawn by the app rather than the system bar, with Back and, in portrait, the sidebar button in the same row), Home with the sync status first (one button, always the next useful action, Resume included while paused), the next due dates and the newest announcements side by side under it and the last four files as rows that open in Files, rounded pill buttons, and English/Turkish wording. Home, Sync activity, Announcements, Calendar (due dates), Courses, Settings, and the offline file browser work. Google Calendar, automatic background sync, notes PDFs, and choosing another destination are visibly labelled **Coming soon / Çok yakında** and have no tap actions.

## First run

On a fresh install the app opens on a full-screen first-run page instead of Home: the logo, "Your course files, on your iPad.", the school as one menu row (with "Other school…" for an address), **Sign in to Blackboard** and a language menu. There is no sidebar or top bar until the first Blackboard sign-in, which goes through the usual sign-in sheet. A student who later signs out and has no downloaded files sees the same welcome as a card on Home and Courses, with only Settings in the top bar; with downloaded files the top bar and the Courses list stay as usual so the files remain reachable offline, and Home shows the welcome card above the recent downloads. The decision and its one stored flag are `FirstRun` in the package (`Support/FirstRun.swift`). The app account's sign-in, once it exists, calls `AppModel.appAccountDidSignIn()`; until then the first launch of a fresh install calls it. An update where Blackboard was already signed in never shows the full-screen page.

## Install on a physical iPad

1. In this folder, copy `Signing.local.xcconfig.example` to `Signing.local.xcconfig` and set `DEVELOPMENT_TEAM` to your Apple Developer Team ID and `BLACKBOARD_SYNC_BUNDLE_ID` to a unique bundle ID you own (replacing placeholder `com.example.BlackboardSync`). The file is gitignored, so `project.pbxproj` stays clean and pulls never conflict; there is no need to touch the **Signing & Capabilities** tab (edits there would be saved into the shared project). Automatic signing is already on, and the test targets get the same team and the bundle ID plus `Tests`/`UITests`. Open (or reopen) the project afterwards. No special entitlements are required.
2. Connect and trust the iPad, enable **Settings → Privacy & Security → Developer Mode**, select the iPad in Xcode, then Run. Approve developer trust on the iPad if requested. The target is iPad-only and supports portrait, landscape, split navigation, and system light/dark appearance.
3. The default school is `https://blackboard.istun.edu.tr`, matching desktop configuration. Before signing in, change it to another HTTPS origin if needed. Sign out before changing schools.
4. Tap **Sign in to Blackboard**, finish the school's sign-in/MFA in the embedded browser, then **Continue** when Blackboard opens. This captures app-owned school cookies and verifies `users/me`; the account's initials appear at the top right, and tapping them shows who is signed in and Sign out (or Reconnect/Sign in); Settings is the gear beside them. No school password is handled by the native app.
5. Open **Courses**, choose the courses to mirror, then **Sync now** on Home's status card. All discovered current-term courses are selected initially; an explicit empty selection remains empty on relaunch. **Sync on app open** is off by default and can be enabled in Settings.
6. Open a course's folder, preview with **Open**, or export with **Share**. Ordinary files are also in **Files → On My iPad → Blackboard Sync → University → term → course**. Files remain available offline and after sign-out. Deleting the app removes its container; export files you want to keep first.

This target has a different bundle ID and dedicated WebKit store from the proof. Sign in once in this app; it does not import the proof's cookies or downloads.

## Launch and introduction

- The launch screen (`UILaunchScreen` in `Info.plist`) is the app icon's navy (`LaunchBackground`) with the logo centred (`LaunchLogo`, 168 pt), the same in light and dark mode. The in-app splash (`SplashView` in the package) starts from that exact frame, so there is no white flash or jump: the logo grows to 196 pt, a halo and the name come in, and after about 1.3 s it fades to the app. With Reduce Motion nothing moves; the launch frame only fades.
- On first launch the five-page introduction follows (`OnboardingView`; pictures are the `Onboarding*` vector assets, copy in English and Turkish in `Onboarding/Onboarding.swift`): swipe or Continue, Get started on the last page, Skip at the top right on every page; either opens the full-screen first run on a fresh install (see First run). VoiceOver reads the page indicator as "Page 2 of 5" and can change the page from it. Whether it was seen is kept in one place, `OnboardingRecord` (`onboardingSeenVersion` in the app's defaults). **Settings › About & privacy › Show the introduction** opens it again.
- Debug UI tests that pass `--ui-testing` skip the introduction; `--ui-testing-onboarding` shows it whatever was saved and `--ui-testing-hold-splash` keeps the splash on screen for screenshots. Release builds ignore these flags.

## Sync and storage behavior

- **Pause syncing / Resume syncing** at the top right works like the Mac's: pausing ends a running sync (its completed files are kept) and nothing syncs, by hand or on app open, until resumed; Home shows **Paused** and the button turns into an accent-colored play button. The pause survives relaunch. Resuming syncs right away when Sync on app open is on. It is available once signed in, and a pause already set can always be lifted.
- Current-term discovery uses memberships, expanded courses with detail fallback and public/private term metadata, and follows the desktop rule (`Term.current`, a twin of `choose_current_terms` in `sync.py`): the latest-started dated term plus every term running now, a 30-day lead, undated terms dated by their newest course without pushing out a running term, and term names read for their year and season when nothing is dated. Closed (No/Disabled) memberships and courses, Organizations and courses opening with a closed term are skipped; courses without a term are synced under "No term". Records of one semester under two names (Turkish/English/Arabic) merge as on desktop and keep the school's own name; a term keeps the folder its courses are already in. `TermScenarioTests` checks the 28 desktop school setups (`BlackboardSyncTests/Fixtures/term_scenarios.json`, a copy of `tests/fixtures/term_scenarios.json`).
- Before the first download at a new school whose current term is not clear, the app asks first, as the desktop apps do (`Core/TermConfirm.swift`, a twin of `term_confirm.py`). The term is not clear when a current term has no dates or dates left from an earlier year, current terms started on different days, or a term's name gives no year and season. Sync now (or Sync on app open) then downloads nothing and shows a card with the terms and courses found. Its ticks are the selection of **Courses**: every course found at a new school, unless the student already unticked some there. **Confirm** saves the ticks as that selection and the school as confirmed in the library, then syncs; it is asked once per school. **Not now**, or closing the card, saves nothing, and the next sync asks again. A school with state is never asked: a sync has run there, this account has files there, or the library is from before 1.7.1 and holds files (every existing user, such as the first school's). `TermConfirmTests` checks the decision on the same 28 setups.
- Files go to `Documents/University/<term>/<course>/…`. Names follow macOS conventions where practical: readable Unicode/NFC, course code without section suffix, safe path components, extension preservation, and bounded UTF-8 component size. Allocated term/course folders are stable across renames/relaunch and disambiguated across collisions and accounts. Nested folders, attachment collections, and content-body/description/instructor-instruction collection links are crawled. File sync queries no announcements, submissions, grades, or student attempts.
- Three concurrent file transfers at most; folder discovery is serial. Discovery guards recursion at 40 levels or 10,000 already-visited items per course and limits each collection to 100 pages, with explicit errors. Repeated or foreign pagination is rejected. Progress shows discovery, completed/total files, downloads, unchanged files, skips and errors. Sync activity retains up to 1,000 entries. A failing collection/file leaves an error while other files continue; **Retry sync** makes a fresh scan of selected courses and reuses successful checkpoints.
- A private atomic manifest in Application Support records selected IDs, stable paths, SHA-256, remote metadata fingerprints, ETags and Last-Modified values. Secrets and signed embedded URLs are excluded. Completed files checkpoint individually. Interrupted runs are rediscovered on relaunch/retry; completed records avoid duplicate downloads. Temporary response files live outside Documents and are removed on failure/cancellation.
- Unchanged remote content fingerprints skip body requests. Without usable content modification metadata, conditional requests use ETag/Last-Modified and a 304 downloads no body. Servers lacking both metadata and validators require a body request; hashing then avoids replacing an identical copy. A locally missing file is downloaded again. The app does not claim zero network bytes when the server offers no way to verify freshness.
- Files stream to private staging with bounded memory. Audio/video are skipped by name or MIME type; the desktop's decimal **500,000,000-byte** cap is checked against headers and streamed byte count. HTML/XHTML MIME types and HTML-looking prefixes are rejected even when labelled PDF; these responses request reconnection. API 401/redirect/non-JSON responses request sign-in; access-denied 403 errors remain distinct. Validated bytes are committed only after the full response arrives.
- A changed remote file replaces only an unchanged local copy. Local edits/annotations are hashed and preserved; the new remote version is saved beside them as `name (2).ext`, then tracked there. Hash-identical remote bytes leave local annotations alone. File coordination and a second hash check guard save-time edits; an edit race produces a retryable error. Existing untracked files are preserved too. Paths reject traversal and symlinks.
- This pilot preserves local files when remote content disappears, a course is deselected, a school/account changes, or the student signs out. It does not implement deletion propagation or archive migration. Different accounts allocate separate collision-safe folders, while the root file browser can show all files retained on the device.

## Announcements and calendar

The **Announcements** and **Calendar** pages come from `ios/BlackboardSyncFeatures` (see its README for the desktop behavior they follow). `Features/FeatureBridge.swift` hands the package the app's own signed-in `BlackboardAPI` (same cookie transport, tenant-origin checks and sign-in detection as sync; no extra networking, cookie or Keychain code) and the ticked current-term courses from **Courses**. Views get the app's accent and cards through `FeatureTheme.app`.

- The pages read Blackboard live when first shown and on pull-to-refresh: announcements from the public endpoint, then the private one; due dates from gradebook column metadata only. Nothing is stored on disk. With room, the list and the selected item sit side by side; in a narrow split the item opens as a sheet.
- Home shows the three newest announcements and the next three due dates (with "1 deadline today · 3 this week") and links to both pages.
- Changing the course selection reloads pages already shown; changing English/Türkçe or signing in with another account rebuilds them in the new language or account. Signing out clears them.
- States: loading, no courses selected, empty, a course that could not be updated (earlier items kept), Blackboard unreachable/offline ("pull down to try again"), and signed out (a sign-in button). An expired session (401, a login redirect, or HTML instead of JSON) puts the app in the same **Reconnect** state as a sync that hits it; the page shows a Reconnect bar and reloads after reconnecting.

## Session and privacy

The proof's working authentication pieces are reorganized into Session and Core. A dedicated persistent `WKWebsiteDataStore` owns browser/SSO data; the cookie replay transport scopes domain, host-only status, path, Secure and expiry, accepts cookie rotations/deletions, and sends school cookies only to the exact tenant origin. Redirects rebuild requests without forwarding Cookie or Authorization to storage/SSO origins; downloads require HTTPS. URLSession is ephemeral with shared cookies, credentials and caches disabled.

Tenant-bound cookie records are stored in a when-unlocked, device-only Keychain item. Sign-out cancels and awaits current work, invalidates URLSession, deletes the Keychain item, and clears the app's dedicated WebKit data. A Keychain deletion failure stays visible and allows another sign-out attempt. Native code never logs cookies, tokens, response bodies, school URL queries, or identities. Errors retain safe HTTP/network codes and redact underlying diagnostic details. No analytics or relay server is used. Files explicitly shared to another app become that app's responsibility.

### Staying signed in

A Blackboard session ends after about an hour, but the school's single sign-on usually lasts longer. With **Automatic re-sign-in** on (Settings → Sync; on by default) the app follows the Mac's rules (`src/blackboard_sync/session_refresh.py`; here `Session/SessionCare.swift` and `Session/SilentSignIn.swift`):

- While the app is on screen it makes one light `users/me` request every 25 minutes, which also keeps the session alive, and cookies Blackboard rotates are saved. Nothing is sent while signed out or paused, and a running sync counts as the keep-alive.
- When under 30 minutes remain (from the expiry in `BbRouter`), or a request finds the session over, a hidden web view on the sign-in browser's own data store opens Blackboard, at app open as well as while it runs. Blackboard's old cookies go first; the sign-on's cookies stay. The attempt waits at most 45 seconds for the app's own `users/me` check to accept the new cookies, which are then saved to the Keychain exactly as interactive sign-in saves them. A sync or page that found the session over then goes on, and Home shows **Session refreshed automatically** for two hours.
- No password is read, typed or stored, and no form is touched. A visible password field, an account picker, a second factor, a network failure or the timeout ends the attempt silently. A session that still works is kept; one that is over shows **Reconnect** as before. Only the outcome's fixed name goes to the system log (`sso-needs-interaction`, `timeout`, …).
- After a failure, at most one attempt per 10 minutes, across relaunches; after one that worked, no second attempt for a minute. Only one attempt runs at a time, and interactive sign-in cancels a running one and blocks new ones. Switching the setting off stops everything; switching it on again may try right away.
- Leaving the app asks iPadOS for a background refresh (`BGAppRefreshTask`, `com.blackboardsync.session-refresh`, with a 25-second attempt). **iPadOS decides whether and when it runs**, often hours later or not at all, for example if the app is rarely used, Background App Refresh is off or Low Power Mode is on. While the iPad is locked the Keychain is closed, so that run does nothing. The on-screen checks above do not depend on it.

How long this works depends on the school. WebKit keeps a session-only sign-on cookie in memory, so a sign-on that lasts "until the browser closes" may not survive the app being closed; in that case the hidden sign-in stops at the school's page and Reconnect appears. Microsoft sign-ins often last longer with "Stay signed in".

## Simulator build and tests

From this folder, the following exact commands were used on the installed iPad Air 11-inch (M3) simulator (iPadOS 18.4). The first builds the app with the package and runs the app's unit and UI tests; the second runs the package's own tests:

```sh
xcodebuild -project BlackboardSync.xcodeproj -scheme BlackboardSync \
  -destination 'platform=iOS Simulator,id=6A750041-BCF4-4A81-93D2-6208BB031259' -destination-timeout 60 \
  -derivedDataPath /tmp/bbsync-ipad-app-derived \
  CODE_SIGNING_ALLOWED=NO test

(cd ../BlackboardSyncFeatures && xcodebuild test -scheme BlackboardSyncFeatures \
  -destination 'platform=iOS Simulator,id=6A750041-BCF4-4A81-93D2-6208BB031259' \
  -derivedDataPath /tmp/bbsync-ipad-features-derived)
```

`swift test` in `../BlackboardSyncFeatures` also runs the package tests on the Mac host.

For another Mac, use `xcrun simctl list devices available` and replace the destination ID, or use `-destination 'platform=iOS Simulator,name=iPad (A16),OS=latest'`. Use `build` instead of `test` for a simulator-only build. Derived data/test results stay outside the repository. The checked-in project and shared scheme build directly; there is no XcodeGen step.

Unit tests use synthetic cookies, a fake paged API, a fake mirror service and a URLProtocol transport; no school requests run. They cover naming/byte limits/Turkish course codes, traversal/symlinks, stable folder allocation, current-term selection and aliases, the card before the first download at a school with an unclear term (its reasons on the 28 setups, school state, Not now and Confirm), state restoration, explicit empty selections, SHA-256/change detection, modified-local conflicts, missing/untracked files, conditional requests, MIME/size policies, HTML-instead-of-file detection, redaction, cookie boundaries/rotation/redirect isolation, nested content/attachment pagination, embedded files, selected-course filtering, bounded concurrency, per-file retry, cancellation/checkpoint recovery, and session expiry. Feature-wiring tests drive the real `BlackboardAPI` through the URLProtocol transport (JSON, paging links, 401/login redirect/HTML → reconnect, 403/404/5xx, non-JSON, foreign links) and an `AppModel` with the package's fake Blackboard (only ticked courses are read, language switch, refresh after a selection change, sign-out, expired session → Reconnect, unreachable course). The hosted test app skips startup/session restoration under XCTest. Pause tests cover the pause waiting for sign-in, persistence, blocking sync, and ending a running sync; account initials follow the Mac. First-run tests cover the full-screen first run on a fresh install until Blackboard is signed in, the welcome card after a later sign-out, downloaded files keeping the normal app, and the app-account hook (the package tests the stored flag and the decision). A separate UI test target checks the full-screen first run (no sidebar, the language menu, "Other school…", an address that is not HTTPS stopping before any page loads), English/Turkish welcome cards with only Settings in the top bar, the top bar (the account menu without a Settings item, the Settings circle, and on every page, pushed folders included, the title and three equal circles on one line with Back and the edge swipe working), navigation including Home's Open calendar pill, signed-out Announcements/Calendar pages, the remaining inert placeholders, and portrait/landscape layouts; Debug-only `--ui-testing-features` fills Announcements, Calendar and Home from the package's sample Blackboard so the real pages are exercised in both languages; screenshots are attached to the `.xcresult` outside the repository. Debug UI smoke tests pass `--ui-testing` to skip Keychain session restoration, and `-firstRunPending YES` or `NO` to start on the full-screen first run or past it; unsigned simulator launches can otherwise report OSStatus -34018. Release builds ignore this flag. Session persistence and sign-out require the signed physical-iPad checklist.

Record iPad model, OS and app version plus pass/fail notes. Do not capture passwords, MFA codes, cookie values, tokens, SSO screens or signed URLs.

- [ ] Sign in with the real school account/MFA, including an authenticator app switch if needed. Tap Continue and compare Home's account and current-term course list with Blackboard.
- [ ] Deselect several courses, sync a small selected course, and confirm only its files arrive. Include nested folders, a regular attachment, and an Ultra embedded/instruction file. Inspect per-file errors if one collection is unavailable.
- [ ] At a new school whose term is not clear, the first Sync now shows **Check your courses before the first download** and downloads nothing; Not now brings it back on the next sync, Confirm with a course unticked syncs only the ticked ones, and it is not asked again. Signed in at İSTÜN with existing files, no card appears.
- [ ] Run a second sync with no remote changes. Confirm zero new downloads where Blackboard provides modification metadata or validators, and no duplicate copies. Review unchanged/skipped/error counts.
- [ ] Open a PDF with another editor through Files, annotate it, then have a permitted remote update available. Sync and confirm the annotated original remains and the new remote file is saved beside it. Also confirm an unmodified local file updates in place, and a manually deleted local file downloads again.
- [ ] Confirm audio/video and a file over 500 MB are skipped and not exported. Check a login/HTML response never becomes a PDF in the mirror.
- [ ] Disconnect Wi-Fi during a multi-file sync. Review errors and Retry sync after reconnecting. Cancel mid-sync, then sync again; successful files should be reused. Lock/switch apps, force-quit during sync, relaunch and Sync now; partial transfers must not appear as completed files.
- [ ] Preview and Share from a course folder. Find the same nested files in Files, open in another reader, then repeat in airplane mode.
- [ ] Open Announcements and Calendar. Compare with Blackboard and the Mac app: newest announcement first, body text, attached files and **Open in Blackboard**; due dates grouped by day with Upcoming before Past due, in the iPad's local time. Untick a course and confirm its items disappear after the pages reload. Check Home's newest announcements and next due dates.
- [ ] Change English ↔ Türkçe in Settings; labels, Announcements and Calendar update immediately. Verify the remaining Coming soon / Çok yakında row (Google Calendar) is inert.
- [ ] Open Announcements in airplane mode (expect "Blackboard could not be reached"), then reconnect and pull down.
- [ ] Pause during a sync: the sync stops, Home shows Paused, Sync now is gone and relaunching (with Sync on app open on) starts no sync. Resume: the play button turns back into Pause and, with Sync on app open on, a sync starts.
- [ ] Turn Sync on app open on/off, relaunch and verify the chosen behavior. Course selection (including selecting none) survives relaunch. Test a late session expiry: the app must offer Reconnect (also from Announcements/Calendar), with existing offline files retained.
- [ ] Sign out while idle and during a sync. Confirm the native session and app WebKit state clear, no transfer continues saving files, and offline documents remain. Relaunch without a session; no school API request should start until sign-in. A school/IdP may independently retain device-wide SSO.

- [ ] Automatic re-sign-in (Settings → Sync, on by default). Sign in, note the time, keep the app open past the session's end (about an hour) without syncing: no Reconnect should appear, and Home should show **Session refreshed automatically**. Note how long the sessions and the school's sign-on actually last.
- [ ] Force-quit the app, reopen it after the session has ended: Home should recover without Sign in. If Reconnect appears instead, the school's sign-on is probably session-only (try "Stay signed in"). Then leave the app in the background for an hour or more and reopen it the same way.
- [ ] Background refresh: leave the iPad unlocked and charging with the app in the background for a few hours, then open it and see whether the session is still alive. iPadOS may simply not run it; a miss here is not a bug if the open still recovers.
- [ ] Turn the setting off: the session should end after about an hour and Reconnect should appear as before. While the school asks for a password or second factor, confirm nothing is filled in or submitted and Reconnect appears within about a minute.

## Pilot limits and parity follow-ups

The proof's real-school authentication worked on the owner's iPad; this new app still requires the physical-device checklist. Simulator fixtures cannot establish institutional SSO behavior, actual attachment metadata/validators, device Files editing, or network behavior under suspension.

Sync runs while the app is active (only the session check above runs in the background). Entering the background cancels cooperatively; return and Sync now to continue, or enable Sync on app open. Transfers restart per incomplete file; there is no HTTP Range resume or scheduled/background transfer service. Byte-level progress for a single large file, a Files provider extension/external destination, advanced rich-text-to-PDF generation, full arbitrary HTML parsing and distribution/App Store readiness are future work. Embedded discovery supports Blackboard collection/upload attributes and common tags, rather than a general web crawler. No background timing promise is made.

The practical iPad adaptations are immediate settings persistence (no Save/restart step), an in-app folder browser instead of a Finder button, native Open/Share, and system SwiftUI layout. Term/course folder naming follows desktop semantics; shorter component budgets and numbered collision suffixes are used on iPad. Existing allocations remain stable rather than migrating a renamed course's local folder. These details should be compared against representative owner courses before broader distribution.
